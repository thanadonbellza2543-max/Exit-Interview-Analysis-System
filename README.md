# ระบบวิเคราะห์ Exit Interview

เว็บช่วยสรุปบทสัมภาษณ์พนักงานลาออก — โยนข้อความหรือไฟล์ Excel ลงไป ได้รายงานที่จัดหมวดเหตุผล
จัดอันดับความรุนแรง ชี้ประเด็นที่ต้องเฝ้าระวัง และเสนอสิ่งที่ควรทำต่อ

**การวิเคราะห์ทำในเบราว์เซอร์ทั้งหมด** — ไม่ใช้ AI API ไม่มีค่าใช้จ่ายต่อการวิเคราะห์
และข้อความบทสัมภาษณ์ไม่เคยถูกส่งไปประมวลผลที่ไหน

ใช้ได้ 2 โหมด สลับกันด้วยการใส่/ไม่ใส่ค่า Supabase ใน `assets/config.js`

| | โหมดคนเดียว | โหมดทีม |
|---|---|---|
| ต้องตั้งค่าอะไร | ไม่ต้อง | Supabase + GitHub Pages |
| ล็อกอิน | ไม่ต้อง | ต้องล็อกอิน |
| ประวัติเก็บที่ไหน | เบราว์เซอร์ของแต่ละคน | ฐานข้อมูลกลาง ทุกคนเห็นชุดเดียวกัน |
| แชร์งานกัน | ส่งไฟล์ JSON หากัน | เห็นทันทีอัตโนมัติ |
| เหมาะกับ | ลองใช้ / ใช้คนเดียว | ทีม HR ใช้จริง |

ดับเบิลคลิก `index.html` ไม่ต้องติดตั้งอะไร ใช้ได้แม้ไม่มีอินเทอร์เน็ต

> - ตอนออฟไลน์ ฟอนต์จะเป็นฟอนต์ระบบ และอ่าน `.xlsx` ไม่ได้ (ให้ Save As เป็น **CSV UTF-8**)

>   และปิดตัวเลือก “บันทึกลงประวัติ” ให้เอง — ส่วนวิเคราะห์และส่งออกไฟล์ยังใช้ได้ครบ
>   ถ้าอยากได้ประวัติด้วย ให้เปิดผ่านเซิร์ฟเวอร์ในเครื่อง:
>
> ```powershell
> Set-Location D:\toyota-exit-ai; python -m http.server 5173
> ```
> แล้วเปิด `http://localhost:5173`

## โหมดทีม — ติดตั้งบน GitHub Pages + Supabase

ใช้เวลาประมาณ 20 นาที ทำครั้งเดียว หลังจากนั้นทีมแค่เปิดลิงก์แล้วล็อกอิน

### 1. สร้างฐานข้อมูลบน Supabase

1. สร้างโปรเจกต์ใหม่ที่ [supabase.com/dashboard](https://supabase.com/dashboard)
2. **SQL Editor → New query** → เปิดไฟล์ [`supabase/schema.sql`](supabase/schema.sql)
   ก็อปเนื้อหา **ทั้งไฟล์** มาวาง → **Run**

จะได้ตาราง `exit_interviews`, ตารางสิทธิ์ `app_users`, view สำหรับทำรายงาน
และ Row Level Security ครบ

> ⚠️ ต้องก็อป **เนื้อหาในไฟล์** มาวาง ไม่ใช่ชื่อไฟล์ — SQL Editor อ่านไฟล์จากเครื่องคุณไม่ได้

### 2. สร้างบัญชีให้ทีม HR

ระบบ**ไม่เปิดให้สมัครเอง** ผู้ดูแลสร้างบัญชีให้เท่านั้น

1. **Authentication → Users → Add user** ใส่อีเมล/รหัสผ่าน ติ๊ก *Auto Confirm User* (ทำซ้ำทุกคนในทีม)
2. ปิดการสมัครเองที่ **Authentication → Sign In / Providers → Email** → ปิด *Allow new users to sign up*
3. กำหนดสิทธิ์ผู้ดูแลใน **SQL Editor** (เปลี่ยนอีเมลให้ตรง):

```sql
insert into public.app_users (user_id, role, full_name)
select id, 'admin', 'ชื่อผู้ดูแล' from auth.users where email = 'hr@company.co.th'
on conflict (user_id) do update set role = excluded.role;
```

**ทุกคนที่ล็อกอินได้จะเห็นข้อมูลทั้งหมด** เพราะเป็นเครื่องมือของทีมเดียวกัน
ต่างกันแค่ `admin` ลบรายการของคนอื่นได้ ส่วน `member` ลบได้เฉพาะของตัวเอง

### 3. อัปโค้ดขึ้น GitHub

```powershell
Set-Location D:\toyota-exit-ai
git init
git add .
git commit -m "ระบบวิเคราะห์ Exit Interview"
git branch -M main
git remote add origin https://github.com/<ORG>/<REPO>.git
git push -u origin main
```

### 4. เปิด GitHub Pages และใส่ค่า Supabase

1. **Settings → Pages → Source** เลือก **GitHub Actions**
2. **Settings → Secrets and variables → Actions → Variables → New repository variable** เพิ่ม 2 ตัว
   (ค่าจาก Supabase → **Project Settings → API**)

   | ชื่อ | ค่า |
   |---|---|
   | `SUPABASE_URL` | `https://xxxxxxxx.supabase.co` |
   | `SUPABASE_ANON_KEY` | คีย์ยาว ๆ ที่ขึ้นต้นด้วย `eyJ...` |

3. push อีกครั้ง (หรือ **Actions → Deploy to GitHub Pages → Run workflow**)

เว็บจะขึ้นที่ `https://<ORG>.github.io/<REPO>/` — ส่งลิงก์นี้ให้ทีมได้เลย

> **anon key เปิดเผยได้โดยการออกแบบ** ปลอดภัยที่จะอยู่ในหน้าเว็บ
> เพราะทุก query ถูกบังคับด้วย Row Level Security และต้องล็อกอินก่อนเสมอ
> **ห้ามใส่ `service_role` key ลง repo เด็ดขาด** — คีย์นั้นข้าม RLS ได้ทั้งหมด

> ถ้า repo เป็น **Public** ตัวหน้าเว็บจะเปิดสาธารณะ (แต่ข้อมูลพนักงานไม่ได้อยู่ในโค้ด
> คนนอกเปิดได้ก็เจอแค่หน้าล็อกอิน) ถ้าต้องการปิดหน้าเว็บด้วย ต้องใช้ repo Private
> พร้อม GitHub Pages แบบ private ซึ่งต้องใช้แผน Enterprise

### 5. ทดสอบ

เปิดลิงก์ → ต้องเจอหน้าล็อกอิน → ล็อกอินแล้วมุมขวาบนต้องขึ้น **👥 ใช้งานร่วมกันทั้งทีม**
ลองวิเคราะห์ 1 คนแล้วให้เพื่อนเปิดดู ต้องเห็นรายการเดียวกันในแท็บ **ประวัติ**

## ใช้ยังไง

| แท็บ | ทำอะไร |
|---|---|
| **วิเคราะห์รายคน** | ลาก **ฟอร์มสัมภาษณ์ `.xlsx` ของบริษัท** มาวางได้เลย (ระบบกรอกชื่อ แผนก ตำแหน่ง ให้อัตโนมัติ) หรือวางข้อความ / ลากไฟล์ `.txt` → กดวิเคราะห์ |
| **ทั้งไฟล์** | รองรับ 2 รูปแบบ ระบบตรวจให้เอง — **ฟอร์มสัมภาษณ์ของบริษัท** (1 ไฟล์ = 1 คน ลากมาพร้อมกันกี่ไฟล์ก็ได้) หรือ **ตารางรวม** (1 แถว = 1 คน ระบบเดาคอลัมน์ให้) พร้อมแดชบอร์ดภาพรวม |
| **ประวัติ** | ผลสะสม ค้นหา/กรองตามวันที่ แผนก ผู้วิเคราะห์ · รวมไฟล์จากเพื่อนร่วมทีม · **ดูภาพรวมรวมทุกคน** |
| **ผู้บริหาร** | แดชบอร์ดระดับองค์กร — แนวโน้มรายเดือน · เทียบกับช่วงก่อนหน้า · หน่วยงานเรียงตามความเสี่ยง · เรื่องที่ต้องตัดสินใจ · พิมพ์เป็นรายงานได้ |
| **คำสำคัญ** | เพิ่มคำเฉพาะขององค์กร (ชื่อไลน์ ชื่อระบบ คำแสลง) เพื่อให้ผลแม่นขึ้น |
| **วิธีอ่านผล** | อธิบายว่าระบบทำงานยังไง เชื่อได้แค่ไหน และจุดที่ต้องระวัง |

กด **ใส่ตัวอย่าง** ในแท็บแรกเพื่อลองดูผลทันที หรือลองโหมดทั้งไฟล์ด้วย [`sample-data.csv`](sample-data.csv)

### รองรับฟอร์มสัมภาษณ์ของบริษัทโดยตรง

ฟอร์มที่ใช้อยู่ (คำถามคอลัมน์ซ้าย · **คำตอบ** · **Comment** โดยแต่ละหมวดใช้ merged cell)
ลากเข้ามาได้เลยไม่ต้องแปลงอะไร ระบบจะ:

- ดึง **ชื่อ-นามสกุล · ชื่อเล่น · แผนก · ฝ่าย · ตำแหน่ง · ผู้สอบถาม · วันที่** จากหัวฟอร์มอัตโนมัติ
- อ่านเฉพาะ **คำตอบ** และ **Comment ของผู้สัมภาษณ์** โดย **ตัดข้อความคำถามทิ้ง**
  (สำคัญมาก เพราะคำถามในแม่แบบมีคำว่า “หัวหน้า” “เพื่อนร่วมงาน” “ลาออก” อยู่แล้วทุกไฟล์
  ถ้านับด้วยจะได้ผลเหมือนกันหมดทุกคน)
- เก็บช่องเขียนอิสระท้ายฟอร์มด้วย
- ลากมาพร้อมกันหลายไฟล์ได้ แล้ววิเคราะห์รวดเดียวพร้อมแดชบอร์ด

ก่อนกดวิเคราะห์ กด **“ดูว่าระบบอ่านอะไรจากแต่ละไฟล์ได้บ้าง”** เพื่อตรวจว่าอ่านถูกไฟล์ถูกช่อง

> ถ้าฟอร์มถูกแก้โครงสร้าง ระบบจะยึดจากแถวที่มีคำว่า **คำตอบ** และ **Comment** อยู่ด้วยกัน
> เป็นตัวบอกว่าแถวนั้นคือหัวหมวด — ตราบใดที่ยังมีสองคำนี้ในแถวเดียวกัน ระบบก็ยังอ่านได้
> ถ้าเปลี่ยนคำเรียก ให้แก้ที่ `parseFormWorkbook` ใน `assets/app.js`

ส่งออกได้เป็น **CSV** (เปิดใน Excel ภาษาไทยได้เลย) · **JSON** · หรือสั่ง**พิมพ์**เป็นรายงาน

## การทำงานร่วมกันในทีม

### โหมดทีม (ตั้งค่า Supabase แล้ว)

ทุกอย่างเป็นอัตโนมัติ — ใครวิเคราะห์อะไร คนอื่นเปิดแท็บ **ประวัติ** ก็เห็นทันที
ไม่ต้องส่งไฟล์หากัน

- **ตั้งชื่อผู้วิเคราะห์ครั้งเดียว** ที่แท็บ *ประวัติ* → ช่อง **ชื่อผู้วิเคราะห์**
  ชื่อนี้ติดไปกับผลทุกครั้ง ทำให้กรองดูงานของแต่ละคนได้
- **กันข้อมูลซ้ำที่ระดับฐานข้อมูล** — ถ้าสองคนอัปโหลดไฟล์ชุดเดียวกัน ระบบบันทึกครั้งเดียว
  (ใช้ unique index บนลายนิ้วมือของรายการ)
- **ปุ่มล้างลบเฉพาะรายการที่ตัวเองสร้าง** ยกเว้นผู้ที่มีสิทธิ์ `admin`
- **ปุ่มส่งออก/นำเข้ายังใช้ได้** สำหรับสำรองข้อมูล หรือดึงงานเก่าจากเครื่องที่เคยใช้โหมดคนเดียว
  เข้ามารวมในฐานข้อมูลกลาง

### โหมดคนเดียว (ยังไม่ได้ตั้งค่า Supabase)

รวมงานกันผ่านไฟล์: แต่ละคนกด **ส่งออกเพื่อแชร์** → ส่งไฟล์ให้คนที่ทำสรุปภาพรวม →
คนนั้นกด **รวมไฟล์จากทีม** เลือกทีเดียวหลายไฟล์ได้ ระบบข้ามรายการซ้ำให้เอง

### ดูภาพรวมของทั้งทีม

ทั้งสองโหมดใช้ปุ่มเดียวกัน — แท็บ **ประวัติ** → **ดูภาพรวมรวมทุกคน**
ได้แดชบอร์ดจากข้อมูลสะสมทั้งหมด กรองตามช่วงวันที่ · แผนก · ผู้วิเคราะห์
แล้วดาวน์โหลด CSV หรือสั่งพิมพ์เป็นรายงานส่งผู้บริหารได้

## ผลวิเคราะห์ประกอบด้วยอะไรบ้าง

หน้าผลเรียงตามลำดับที่ HR ต้องตัดสินใจจริง — **เหตุผลหลัก** ตัวใหญ่พร้อมข้อความอ้างอิงอยู่บนสุด
ถัดมาคือ **ธงแดงที่ต้องตรวจก่อนปิดเคส** (แสดงเฉพาะเมื่อพบ) แล้วจึงเป็นสรุปสถานะ 4 ช่อง
ปัจจัยรองที่กดดูข้อความอ้างอิงได้ และ **สิ่งที่ควรทำต่อ** เป็นข้อ ๆ
ส่วนรายละเอียดยาว ๆ (สรุปย่อ คำพูดสำคัญ คะแนนทุกหมวด) พับเก็บไว้ท้ายสุด กดเปิดเมื่อต้องการ


- **ประเด็นหลัก** และ **สรุปย่อ** — เรียบเรียงจากสิ่งที่ตรวจพบ
- **หมวดปัจจัย 13 หมวด** พร้อมระดับความรุนแรง 1–5 และประโยคอ้างอิงจากต้นฉบับ
  (ค่าตอบแทน · ความก้าวหน้า · หัวหน้างาน · เพื่อนร่วมงาน · ภาระงาน · OT/กะ · ความปลอดภัย ·
  ฝึกอบรม · เดินทาง · นโยบาย · ได้งานใหม่ · ศึกษาต่อ · ส่วนตัว)
- **น้ำเสียงโดยรวม** และ **องค์กรน่าจะรั้งไว้ได้หรือไม่**
- **สิ่งที่พนักงานชื่นชม** — แยกออกจากสาเหตุการลาออก
- **คำพูดสำคัญ** ยกจากต้นฉบับตรง ๆ
- **ประเด็นเฝ้าระวัง** — การคุกคาม · เลือกปฏิบัติ · ความปลอดภัย · ค่าจ้าง/กฎหมายแรงงาน · หมดไฟ · สูญเสียองค์ความรู้
- **ข้อเสนอแนะตั้งต้น** พร้อมระบุผู้รับผิดชอบและระดับความสำคัญ

โหมดทั้งไฟล์เพิ่มแดชบอร์ด: ปัจจัยที่พบบ่อยที่สุด · สัดส่วนน้ำเสียงลบ ·
**ตารางแยกตามหน่วยงาน** (จำนวนลาออก · น้ำเสียงลบ · ธงแดง) · ประเด็นเร่งด่วนรวมทุกคน ·
ข้อเสนอแนะระดับองค์กร

และรายชื่อพนักงานที่ **ค้นหา / เรียง / กรอง** ได้ — เรียงตามความรุนแรงเป็นค่าเริ่มต้น
กดตัวกรอง **🚩 มีธงแดง** เพื่อดูเฉพาะคนที่ต้องตามก่อน หรือกรองรายแผนกในคลิกเดียว
ช่องค้นหาไล่หาทั้งในเนื้อบทสัมภาษณ์ ไม่ใช่แค่ชื่อ

ระบบ **จับคู่คำสำคัญภาษาไทย** ไม่ได้ใช้โมเดล AI — ทุกอย่างคำนวณด้วย JavaScript ในเบราว์เซอร์

ให้คะแนนความรุนแรงจาก 4 สัญญาณ: จำนวนคำที่ต่างกันที่พบ · จำนวนครั้งที่ถูกพูดถึง ·
คำขยายความรุนแรงในประโยคเดียวกัน (“มาก” “ตลอด” “ทนไม่ไหว”) · และตำแหน่งที่ปรากฏในบทสัมภาษณ์
แล้วผสมเกณฑ์สัมบูรณ์กับเกณฑ์สัมพัทธ์เทียบกับหมวดอื่นในบทสัมภาษณ์เดียวกัน

มีกลไกกันพลาดที่ใส่ไว้แล้ว:

- **ตรวจการปฏิเสธ** — “ไม่มีปัญหาเรื่องเงิน” ไม่ถูกนับเป็นปัญหาค่าตอบแทน
- **แยกคำชมออกจากคำบ่น** ที่ระดับประโยค — “เพื่อนร่วมงานดีมาก” ไม่ถูกนับเป็นสาเหตุการลาออก
- **ตัดบรรทัดคำถามของผู้สัมภาษณ์ทิ้ง** — “เรื่องค่าตอบแทนล่ะครับ” ไม่ถูกใช้เป็นหลักฐาน
- **หมวดข้อเท็จจริง** (ย้ายบ้าน เรียนต่อ ได้งานใหม่) นับเสมอแม้อยู่ในประโยคน้ำเสียงบวก
- **ขอบเขตคำอังกฤษสั้น** — “ot” ไม่ไปจับตัวอักษรกลางคำว่า “toyota”

### ข้อจำกัดที่ต้องรู้

| ทำได้ดี | ทำไม่ได้ |
|---|---|
| จัดหมวดและจัดอันดับเหตุผลได้เร็วมาก | **ไม่เข้าใจบริบท** — ถ้าพนักงานบอกว่าลาออกเพราะเงิน แต่เนื้อหาจริงคือเรื่องหัวหน้า ระบบจับไม่ได้ |
| ยกประโยคจากต้นฉบับ ไม่แต่งข้อความขึ้นเอง | **ไม่เข้าใจการประชด** — “หัวหน้าดีมาก ดีจนไม่เคยตอบอะไรเลย” จะถูกนับเป็นบวก |
| สแกนหาคำเสี่ยงได้ครบทุกไฟล์โดยไม่พลาด | **รู้จักเฉพาะคำในพจนานุกรม** — คำที่ไม่รู้จักจะไม่ถูกจับเลย ต้องเพิ่มเองในแท็บ “คำสำคัญ” |
| รวมภาพหลายร้อยคนได้ในพริบตา | **สรุปย่อเป็นการเรียบเรียงจากแม่แบบ** ไม่ใช่การเขียนใหม่แบบเข้าใจเนื้อหา |

**ใช้เป็นตัวช่วยร่างรายงานและคัดกรองเบื้องต้น — HR ต้องอ่านต้นฉบับยืนยันทุกครั้ง**
โดยเฉพาะธงเฝ้าระวังเรื่องการคุกคามหรือความปลอดภัย ต้องสอบข้อเท็จจริงกับคนจริงเสมอ
ห้ามใช้ผลจากระบบนี้ตัดสินเรื่องบุคคลโดยลำพัง

## ความเป็นส่วนตัว

- **การวิเคราะห์ทำในเบราว์เซอร์ทั้งหมด** ข้อความบทสัมภาษณ์ไม่เคยถูกส่งไปประมวลผลที่ไหน
  ไม่ว่าจะใช้โหมดไหน
- **โหมดคนเดียว** — ไม่เรียกเซิร์ฟเวอร์ใด ๆ เลย (ยกเว้นโหลดฟอนต์กับไลบรารีอ่าน Excel
  ครั้งแรก ซึ่งไม่ได้ส่งข้อมูลของคุณไปด้วย) ข้อมูลอยู่ใน `localStorage` ของเครื่องนั้น
  ใช้เครื่องร่วมกับคนอื่นให้กด **ล้างทั้งหมด** เมื่อใช้เสร็จ
- **โหมดทีม** — ผลวิเคราะห์ถูกเก็บที่ Supabase ต้องล็อกอินก่อนจึงอ่านได้ และทุก query
  ผ่าน Row Level Security เสมอ
- ตารางมีคอลัมน์ `raw_text` เก็บบทสัมภาษณ์ต้นฉบับไว้เพื่อวิเคราะห์ซ้ำเมื่อเพิ่มคำสำคัญใหม่
  **ถ้านโยบายบริษัทไม่อนุญาตให้เก็บ ให้ลบคอลัมน์นี้ทิ้งจาก schema ได้ ระบบยังทำงานปกติ**
- ควรตกลงกันในทีมให้ชัดว่าข้อมูลเก็บนานเท่าไร ใครลบได้ ก่อนเริ่มใช้กับข้อมูลจริง

## ปรับแต่ง

**เพิ่ม/แก้คำสำคัญ** — ใช้แท็บ “คำสำคัญ” ในหน้าเว็บ (บันทึกในเครื่อง ไม่ต้องแก้โค้ด)

**เพิ่มหมวดใหม่ หรือแก้ข้อเสนอแนะประจำหมวด** — แก้ `CATEGORIES` ที่หัวไฟล์
[`assets/engine.js`](assets/engine.js) แต่ละหมวดมี `label`, `kw` (คำสำคัญ), `action` (ข้อเสนอแนะ)
และ `factual: true` สำหรับหมวดที่เป็นข้อเท็จจริงไม่ใช่คำบ่น

**แก้เกณฑ์ให้คะแนน** — ดูส่วน 5.1 ใน `engine.js`

**แก้ประเด็นเฝ้าระวัง** — แก้ `RISKS` ใน `engine.js`

## โครงสร้างไฟล์

```
index.html                     หน้าเว็บ
assets/engine.js               เครื่องมือวิเคราะห์ — พจนานุกรม เกณฑ์คะแนน การสรุป
assets/app.js                  ส่วนติดต่อผู้ใช้ อัปโหลดไฟล์ ประวัติ ส่งออก
assets/cloud.js                ชั้นเชื่อมต่อ Supabase (ล็อกอิน + อ่าน/เขียนข้อมูลกลาง)
assets/config.js               ค่า Supabase — ปล่อยว่าง = โหมดคนเดียว
assets/style.css               ธีม (รองรับโหมดมืด) และสไตล์สำหรับสั่งพิมพ์
supabase/schema.sql            ตาราง + RLS + view รายงาน
sample-data.csv                ไฟล์ตัวอย่างสำหรับทดสอบโหมดทั้งไฟล์
.github/workflows/deploy.yml   deploy ขึ้น GitHub Pages + ใส่ค่า Supabase อัตโนมัติ
legacy-ai-version/             เวอร์ชันแรกที่ใช้ Claude API สรุป (เก็บไว้เผื่อกลับไปใช้)
```

### เวอร์ชันที่ใช้ AI จริง

โฟลเดอร์ `legacy-ai-version/` เก็บเวอร์ชันแรกที่เรียก Claude API ผ่าน Supabase Edge Function ไว้ครบ
เวอร์ชันนั้นเข้าใจบริบทได้จริง (จับได้ว่าเหตุผลที่พูดกับเหตุผลจริงไม่ตรงกัน) แต่ต้องมี API key
ต้องตั้งค่า Supabase และมีค่าใช้จ่ายราว 1–3 บาทต่อการสรุปหนึ่งคน
วิธีติดตั้งอยู่ใน `legacy-ai-version/README-ai-version.md`
